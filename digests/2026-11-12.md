# Agent 开发日报 2026-11-12

覆盖时间：约 2026-11-11 至 2026-11-12 上午（Asia/Bangkok UTC+7）。官方文章日期按发布方页面标注；HN 分数为今早抓取时的数值。标注“据 AINews 汇总”的内容是二手信息。

关键词：AutoR&D 与 RSI、AWS Emulator、Gemini Decisions API、Agent 准入之争、MCP 发布节奏

## 今日要点
1. “Agent 自己做研发”出现两个具体样本：Salesforce 的 SFR-AutoR&D 已在生产里自主改进嵌入模型；Anthropic 路演视频称 Mythos 三天内几乎无人工介入就把 Claude 移植到 AMD GPU，并公开把递归自我改进（RSI）写进算力叙事。
2. AWS 发布 AWS Emulator：一个完全由 Agent 编写和测试、覆盖 200 多个 AWS 服务的本地模拟环境，CC0 开源，核心观点是“工程师的工作变成给 Agent 造规格、测试和合并门禁”。
3. Google 推出 Gemini Decisions API：不生成文本、一次前向给封闭选项打分的“决策模型”，定位为 Agent 的路由、工具选择和策略检查控制面。
4. 平台对 Agent 的态度分化：United Airlines 宣布禁止第三方个人 AI Agent 代订机票。其他：阿里 Qwen4-Max 限时预览，Databricks 二代 Genie，MCP 改为每半年一次规范发布。

## 重点话题

### 1. Agent 做研发：SFR-AutoR&D 进入生产，Anthropic 把 RSI 写进路演

**发生了什么**
- Salesforce AI Research 于 2026-11-11 介绍 SFR-AutoR&D：给定一个目标、一个系统和算力预算，Agent 自己提出假设、实现方法、对照基线做实验，只有证据支持的改进才会保留。它由两个 Agent 组成：AutoR&D-Engineer 在已有代码里找算法和系统优化，TrainForge 探索新的训练方法并在从不参与训练的留出基准上评估，底层是共享 GPU 的 AutoInfra。（[Salesforce, 2026-11-11](https://www.salesforce.com/news/stories/agents-that-improve-ai-models/)）
- 成果：它自主改进了 Data Cloud 检索用的 SFR-Embedding V3；再以开源的 EmbeddingGemma 2 为起点产出 SFR-Embedding v4，在 10 个 MTEB 检索任务上 nDCG@10 提高 6.13 分，整个周期约 80 小时；第二轮约 9 小时的会话把吞吐提高 36%、延迟降低 17%，质量几乎不变。此前它还在 pandas、hnswlib、USearch 上找到过性能提升。（[Salesforce, 2026-11-11](https://www.salesforce.com/news/stories/agents-that-improve-ai-models/)）
- Anthropic IPO 路演视频（Simon Willison 转录）：联合创始人 Tom Brown 称今年首次接入 AMD GPU 时，让 Mythos 去做，三天内基本无人工介入就让 Claude 跑在 AMD 上，几乎 100% 的 kernel 由 Claude 移植或编写；以往接入新芯片平台需要几十名工程师数月。他还把“compute multipliers（算力乘数）”称为核心优势，并说“随着接近递归自我改进，Claude 将能完全自己发现算力乘数”。（[Simon Willison, 2026-11-11](https://simonwillison.net/2026/Nov/11/anthropic-ipo-roadshow/)）
- 据 AINews 汇总：Anthropic 更新后的 S-1 写明，按“观察到或预期 AI 研发加速”的条件，Autonomy 2 能力阈值已被触及，但文件称该判定并非基于当前模型；Vals 的 RSI Index 给 Fable 5.2 打 37.8 分，仅略高于 Opus 5.5 的 37.3，与 Anthropic 主动限制 AI 研发能力的说法一致；DAIR 汇总的 InfraRSI 工作中，Agent 把训练 MFU 从 17.4% 提到 30.0%。（[Latent Space AINews, 2026-11-11](https://latent.space/p/ainews-mercor-750m-series-d-at-20b-valuation-3b-run-rate/)）

**为什么重要**
- 一边是 Anthropic 在对外模型里压低 AI 研发能力，一边是它在内部用 Mythos 做 kernel 移植、并在路演里把 RSI 当增长逻辑讲。对开发者的含义是：最强的“研发 Agent”能力可能先留在实验室内部，对外模型在这类任务上被刻意设限。
- SFR-AutoR&D 的价值在于工程形态而非单个分数：明确的目标、预算、留出评估和“无验证改进就不合入”的门禁。这套结构可以直接借鉴到自己的 autoresearch 或性能优化 Agent 上，而且检索栈（嵌入模型、hnswlib 这类向量索引库）本身就是很适合自动优化的目标。

**接下来关注**
- Salesforce 预告的 CodeEvolve（用 LLM 加进化搜索改进 Java 和 Apex 代码）详细博客；SFR-Embedding v4 是否公开权重。
- Anthropic S-1 中 Autonomy 2 判定的原文表述，以及上市后的信息披露是否会更系统地报告内部研发自动化程度。

### 2. AWS Emulator：Agent 写出来的“本地 AWS”，以及工程师的新职责

**发生了什么**
- AWS 于 2026-11-11 发布 AWS Emulator，给编码 Agent 一个可离线、免费运行的本地 AWS 用来测试。它基于 400 多个 Smithy API 模型、覆盖 200 多个 AWS 服务，全部代码由 Agent 编写和测试，以 CC0 发布，提交历史和 Agent 提的 issue 全部公开，仓库里有一个 “things-that-do-not-work” 目录记录尚未对齐真实 AWS 的行为。（[All Things Distributed, 2026-11-11](https://www.allthingsdistributed.com/2026/11/aws-emulator-and-the-engineers-job-when-agents-write-the-code.html)；[GitHub aws/aws-emulator](https://github.com/aws/aws-emulator)）
- 做法：Agent 先从公开 API 模型推出端到端的 “fidelity tests”，对着真实 AWS 修正测试直到通过，让测试记录真实行为；再写模拟器直到通过同一套测试。最早的 SQS 原型由 Kiro 一个提示词约 15 分钟生成。所有改动要过合并门禁，包括多个从不同攻击角度做对抗审查的安全 Agent，以及阻止 Agent 改动不该碰的代码的确定性检查。（[All Things Distributed, 2026-11-11](https://www.allthingsdistributed.com/2026/11/aws-emulator-and-the-engineers-job-when-agents-write-the-code.html)）
- Swami Sivasubramanian 的亲身例子：他用 Kiro 重写当年花四个月做的 Paxos 锁服务复制引擎，前四个晚上 Agent 没有办法检查自己的结果；给了规格和测试环境后，重写只用了约两小时。（[All Things Distributed, 2026-11-11](https://www.allthingsdistributed.com/2026/11/aws-emulator-and-the-engineers-job-when-agents-write-the-code.html)）

**为什么重要**
- 这和昨天的 AlphaProof Code、Fable 5.2 的 Lean 形式化是同一个方向：Agent 能跑多久、能多可靠，取决于它有没有可执行的验收标准。云服务的本地高保真模拟把“验证环境”从形式化数学扩展到了日常的分布式系统开发。
- “用真实系统校准测试，再让 Agent 追着测试造替身”是一套可复用的方法，适用于任何有公开 API 规格的第三方服务。

**接下来关注**
- AWS 称会在 re:Invent 分享更多细节；社区对其与 LocalStack 等现有工具的保真度比较。

### 3. Gemini Decisions API：给 Agent 的“决策控制面”

**发生了什么**
- Google 于 2026-11-11 推出 Gemini Decisions API 和新模型 `gemini-decision-1`：一次请求传入一份多模态输入（文本、图片、音频、视频、PDF，最多 256K token）和最多 1000 个独立问题，题型为是否判断、2 到 255 选 1、有序评分。模型不逐 token 生成，而是一次前向给候选项打分，返回概率和 0 到 1 的置信度，端到端延迟 150 到 250 ms，价格每百万输入 token $0.10，输出 token 不计费。（[Google Blog, 2026-11-11](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-decisions-api/)）
- 官方列出的用途就是 Agent 基础设施：工具选择、策略检查、模型路由、上下文打分。内部案例包括 Gemini Notebook 用它做实时模型与思考档位路由（日常查询延迟最多降低 40%），以及 Google Search 用它给 MCP 工具做对抗行为检测的安全层。OpenRouter、LangChain、Vercel、LiteLLM、Pydantic AI、Pipecat、LiveKit、OpenCode 正在接入。（[Google Blog, 2026-11-11](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-decisions-api/)）
- 同一趋势的旁证（据 AINews 汇总）：Hugging Face Transformers 新增统一的 `model.decide()` 接口；Amazon 把内部工单打标从 Sonnet 换成决策模型，同等准确率下快 4.5 倍、便宜 44 倍。（[Latent Space AINews, 2026-11-11](https://latent.space/p/ainews-mercor-750m-series-d-at-20b-valuation-3b-run-rate/)）

**为什么重要**
- 多 Agent 系统里大量步骤其实是封闭选择题（下一步调哪个工具、这个请求该给哪个模型、这段输出是否越权）。用生成式大模型做这些判断又慢又贵，还没有校准过的置信度。单独的决策模型让“路由 + 护栏”这一层可以做到毫秒级、并能按置信度转人工。
- 这与昨天 Fable 5.2 和 `/swarm` 的“强模型协调、弱模型执行”结构互补：协调层之外又多了一层便宜的判定层。

**接下来关注**
- 第三方对其校准误差和路由准确率的独立评测；是否会出现开源的同类决策模型。

### 4. Agent 准入之争：United Airlines 封禁第三方个人 Agent

**发生了什么**
- United Airlines 于 2026-11-11 宣布禁止未授权的第三方个人 AI Agent 代旅客订票，理由是共享账号凭证会暴露敏感信息、可能导致意外购买或里程被用，并称 Agent 代办值机可能违反要求旅客亲自确认行李无违禁品的联邦规定；限制会同时通过自有平台和旅行社、聚合平台执行。（[CBS News, 2026-11-11](https://www.cbsnews.com/news/united-airlines-bans-ai-agents-booking-flights/)）
- CNBC 同日报道的背景：Amazon 已屏蔽 Meta 的 Agent Muse，Walmart 则与 Muse 合作；Expedia 和 Booking 在与 OpenAI 合作；Southwest 已向 ChatGPT 用户开放航班库存。（[CNBC, 2026-11-11](https://www.cnbc.com/2026/11/11/united-airlines-ai-agents.html)）

**为什么重要**
- 做消费级 Agent 的瓶颈正在从模型能力转向“对方让不让你进”。凭证代管、需要本人确认的合规步骤、平台不想失去的客户关系，这三点会让“用户的浏览器 Agent 直接登录操作”这条路越来越窄，官方集成（如 ChatGPT 内的商家 Agent）和代理授权协议会更重要。

**接下来关注**
- 其他航空公司和大型电商是跟进封禁还是开放官方接口；是否出现面向 Agent 的标准化委托授权（不交出密码的代理权限）。
