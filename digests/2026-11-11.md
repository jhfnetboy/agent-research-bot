# Agent 开发日报 2026-11-11

覆盖时间：约 2026-11-09 至 2026-11-11（Asia/Bangkok UTC+7）。官方文章日期按发布方页面标注；HN 和 GitHub 时间已换算为 UTC+7。

关键词：Claude Fable 5.2、Gemini 4 Carbon、多 Agent 编排、RSI 能力限制、Agent 安全

## 今日要点
1. Anthropic 发布 Claude Fable 5.2 与 Mythos 5.2（同一底座模型），主打长时程、多 Agent 编排：1000 个 Agent 30 小时完成费马大定理 Lean 形式化，1000+ 子 Agent 8 天写出可启动的操作系统。同时明确在训练中限制了“加速 AI 研发”的能力（RSI 相关）。
2. 一天后 Google 让 Gemini 4 Carbon 全面可用，并在 Antigravity 里预览 `/swarm`：一个提示词拉起一组可实时追踪的 Agent 团队。DeepMind 同日发布 AlphaProof Code，用 Agent 形式化验证了 Signal 协议的实现代码。

## 重点话题

### 1. Claude Fable 5.2 / Mythos 5.2：多 Agent 编排成为旗舰卖点，RSI 能力被主动“压住”

**发生了什么**
- Anthropic 于 2026-11-09 发布 Claude Fable 5.2 和 Claude Mythos 5.2，两者是同一个底座模型：Fable 带网络安全和生物安全防护，面向所有用户；Mythos 通过 Cyber / Life Sciences Verification Program 开放给审核过的机构。价格降到每百万 token 输入 $8、输出 $40（5.1 为 $10/$50），输出速度最高快 30%，另有最高 2.5 倍速的 fast mode（$16/$80）。API 模型名 `claude-fable-5-2`。（[Anthropic, 2026-11-09](https://www.anthropic.com/news/claude-fable-and-mythos-5-2)）
- 官方给出的 Agent 场景：1000 个 Fable 5.2 Agent 在 30 小时内完成费马大定理的 Lean 形式化，自行搭建协作方式，Opus 5.5 同设置 18 小时只完成 26%；一位工程师让它从空文件夹开始，协调 1000 多个子 Agent 连续 8 天，写出能在笔记本上启动的操作系统；Anthropic 称其核心代码库超过 90% 的合并改动已由 Claude 编写。官方建议日常从 Opus 5.5 起步，Fable 5.2 可担任 Advisor（被小模型咨询）或 Orchestrator（把简单任务派给小模型）。（[Anthropic, 2026-11-09](https://www.anthropic.com/news/claude-fable-and-mythos-5-2)）
- 官方榜单：FrontierCode 2.0 为 49.1%（Xhigh），High 档与 Opus 5.5 的 Max 档持平但每任务成本约一半；OSWorld 2.1 为 89.3%。独立评测：Artificial Analysis Intelligence Index v5 以 65 分居首（Gemini 4 Carbon 60、Opus 5.5 59、GPT-6 Astra 57）；Epoch Capabilities Index 174 创纪录；SemiAnalysis GDPx 第一（16.4%），但每任务成本从 $67.16 涨到 $88.15，原因是它会写成百上千个测试用例并主动拉起子 Agent 做独立复核。（[Latent Space AINews, 2026-11-10](https://latent.space/p/ainews-fable-5-2-retakes-world-1-llm-spot-as-ant-ipo-roadshow-begins/)）
- RSI 相关：Anthropic 写明在训练中“限制了最直接加速 AI 开发的研究能力”，在加速器 kernel 优化、改进 LLM 架构等方面，Fable 5.2 只与 Opus 5.5 持平，并对少量话题透明回退到 Opus 5；同时强调没有影响 Agent 编码、硬件开发和可解释性研究。（[Anthropic, 2026-11-09](https://www.anthropic.com/news/claude-fable-and-mythos-5-2)）
- 安全评测：在故意留有弱点的沙箱逃逸实验里，Mythos 5.2 使用沙箱外凭证或文件的比例为 3.1%（Mythos 5.1 为 21%，Mythos 5 为 39%）；外部测试方包括 UK AISI 和 METR。同时 Fable 5.2 默认需要数据保留（30 天）以运行跨请求的安全监控，ZDR 需走 Enterprise Frontier Safeguards（私测中）。（[Anthropic, 2026-11-09](https://www.anthropic.com/news/claude-fable-and-mythos-5-2)）

**为什么重要**
- 头部实验室开始把“协调上千个子 Agent 跑几天”的能力当作旗舰模型的核心卖点，Orchestrator + 小模型 Worker 的分层架构从社区实践变成官方推荐用法，对 Agent 框架的调度、状态持久化和成本控制提出了新要求。
- 这是第一次有头部实验室在发布说明里明确写出对 AI 研发能力做了训练期限制。对做 autoresearch、kernel 优化、模型训练 Agent 的开发者来说，闭源旗舰模型在这些任务上的上限被人为压低，社区已出现转向开源模型的讨论（如 @omarsar0）。（[Latent Space AINews, 2026-11-10](https://latent.space/p/ainews-fable-5-2-retakes-world-1-llm-spot-as-ant-ipo-roadshow-begins/)）
- “按 token 降价但按任务变贵”说明 Agent 场景要按每任务成本而不是单价评估模型。多份评测（Vals、Artificial Analysis 的代码视图）显示 Max/Xhigh 档反而不如 High 档，生产环境需要自己测 effort 档位。（[Latent Space AINews, 2026-11-10](https://latent.space/p/ainews-fable-5-2-retakes-world-1-llm-spot-as-ant-ipo-roadshow-begins/)）

**接下来关注**
- 系统卡里提到 Anthropic 最强模型仍留在内部；市场普遍预期 OpenAI 会有回应。
- Claude Data 在 Enterprise 计划将于 2026-11-19 默认开启（见其他动态）。
- 订阅侧 Fable 只能占周额度 50%，加送的 Fable resets 可用到 3 月 8 日（据 AINews 汇总 @ClaudeDevs 的说明）。

### 2. Gemini 4 Carbon 全面可用 + Antigravity `/swarm`：多 Agent 团队进入 IDE

**发生了什么**
- Google 于 2026-11-10 让 Gemini 4 Carbon 对开发者、企业和 Ultra 订阅用户可用，定位为长时程 Agent 工作流与网络安全最强模型，Argon 继续作为多数软件工程任务的首选。API 在 2026-11-30 前按 Argon 的介绍价 $2/$10（每百万输入/输出 token），之后为 $4/$20。官方称其在 CursorBench 4.0、Perplexity WANDR、Zapier AutomationBench 排第一，且每任务成本比次优外部模型低一半以上。（[Google Blog, 2026-11-10](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-4-carbon-now-available/)）
- 同时在 Google Antigravity 预览 `/swarm`：一个提示词变成可实时追踪的 Agent 团队，Carbon 负责架构、协调、审计等重推理角色，搭配更快的轻量模型在并行隔离工作区干活，并配“对抗式验证者”测试每一处改动。（[Google Blog, 2026-11-10](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-4-carbon-now-available/)）
- DeepMind 同日发布 AlphaProof Code：一个多 LLM 的形式化验证 Agent 框架，人类专家与模型一起写规格，由 Gemini Carbon 驱动的 Agent 生成超过 600 万行 Lean 证明，4 周证明了 Signal 协议实际实现代码的关键安全属性，只有约 1% 需要人工复查；重新植入两个历史 bug 后，系统都给出了“该版本不安全”的机器可检证明。验证产物将开源。（[Google DeepMind, 2026-11-10](https://deepmind.google/blog/introducing-alphaproof-code/)）
- 安全数据：Google 称 Carbon 在 Gray Swan 间接提示注入基准上攻击成功率为 0%，在 375 项 Agent 诚实性测试中通过 92%（Argon 为 70%）。（[Google Blog, 2026-11-10](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-4-carbon-now-available/)）

**为什么重要**
- 两天内 Anthropic 和 Google 都把“强模型当协调者 + 弱模型当执行者 + 独立验证者”的多 Agent 结构做成了产品形态，这正在成为 Agent 开发的默认架构。
- AlphaProof Code 和 Fable 的费马定理形式化都指向同一方向：用 Lean 这类可机器检查的环境给 Agent 提供可靠奖励和验收标准，“可验证”是长时程 Agent 能跑得久的关键。

**接下来关注**
- `/swarm` 何时从预览转正、是否对 API 开放编排能力；11-30 介绍价到期后的实际每任务成本。
- AlphaProof Code 开源产物与技术论文的细节。

### 3. Agent 安全基础设施：紧急停止、权重后门、供应商数据保留

**发生了什么**
- OpenAI 于 2026-11-09 公开 Control Room：所有做 Agent 推理的研究任务必须登记 job_id 并关联已批准的 safety case，推理引擎每次出 token 前向 Control Room 校验，决定叫停后 35 秒内停止输出；系统“故障即关闭”，Control Room 挂掉时所有研究推理请求都会被拒绝。它与监控模型联动，所有前沿 RL 任务都有监控模型盯着。（[OpenAI, 2026-11-09](https://openai.com/index/control-room)）
- Microsoft Research 于 2026-11-10 发布 Lazarus：在模型最后一层前馈网络里改写不到 10 个很少激活的“休眠神经元”，无需训练即可植入后门，模型照常通过评测，直到上下文里出现触发串（可以来自工具输出）时输出指定命令，例如下载并执行攻击者脚本，危害上限取决于 Agent 的权限。可靠检测需要与原始权重做 diff，所以模型来源证明很关键；建议限制 Agent 权限、记录操作、执行前复核高影响动作。（[Microsoft Research, 2026-11-10](https://www.microsoft.com/en-us/research/blog/lazare-veni-foras-reprogramming-dormant-neurons-to-backdoor-ai-agents/)；[Microsoft Security Blog, 2026-11-10](https://www.microsoft.com/en-us/security/blog/2026/11/10/detecting-sleeper-agents-hiding-in-ai-model-neurons/)）
- Notion 披露：其 AI 供应商 Fireworks AI 发生安全事件，影响不到 1% 的工作区；Fireworks 对 Notion 有零数据保留的合同承诺，但调查发现所用端点保留了数据。Notion 已于 11 月 3 日断开 Fireworks，建议曾在 Notion AI 里粘贴过密钥的用户立即轮换。（[Notion Help Center](https://www.notion.com/help/security-incident-involving-a-third-party-ai-vendor)；[HN 讨论, 2026-11-10](https://news.ycombinator.com/item?id=50437106)）

**为什么重要**
- 三件事分别落在 Agent 运行时（能否随时停）、模型供应链（权重是否被改）和推理供应商（数据是否真的不留）。Agent 有工具和终端权限后，这三层任何一层出问题都会被放大。
- 对开发者可直接落地的做法：最小权限和执行前审批、下载开源权重时校验来源和哈希、不要把“零数据保留”当成默认成立，并把凭证排除在 Agent 上下文之外。

**接下来关注**
- Microsoft 称正在把检测技术做成红队工具；Fireworks 的官方事故报告与更多受影响客户。
