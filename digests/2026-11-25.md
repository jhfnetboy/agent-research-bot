## 重点话题

### 1. AI 自主数学与科学：OpenAI 9 篇预印本、DeepMind 量子算法、GPT-6 蛋白质设计

**发生了什么**
- OpenAI 的 openai/math 仓库（README 称内容由“一个未命名的 OpenAI 内部模型”产出，目前 730 篇、约 42% 的顶层结果有 Lean 形式化）在 history.md 新增 11 月 24 日条目：两个结果家族共 9 篇预印本。家族 379“Euclidean tensor geometry”包含《The matrix multiplication exponent is nine fourths》（摘要称任意域上方阵乘法指数为 9/4，且每个 n ≥ 2 的形式算术电路至少需要 n^(9/4)/2 个乘除门，“上界此前已知”）、《An exponential bound for sunflowers》（证明 Erdős 和 Rado 的固定花瓣 sunflower 猜想）以及更强的 VP ≠ VNP 与 Hamiltonian cycle、permanent 电路下界；家族 380 包含《Strongly polynomial linear programming》（确定性强多项式 LP 算法，回答 Smale 第九问题）和《Superpolynomial graph diameter of simple polytopes》（否定多项式 Hirsch 猜想）。提交时间为 2026-11-25 00:04 UTC，即曼谷时间 11 月 25 日 07:04。（[openai/math history.md, 2026-11-24](https://github.com/openai/math/blob/main/history.md)；[CONTENTS.md](https://github.com/openai/math/blob/main/CONTENTS.md)）
- 形式化范围：Lean 文档说明，Valiant 层级的三个严格包含、矩阵乘法指数 9/4（在不含除法的程序模型下）、LP 的强多项式可解性和 Hirsch 反例都有 Comparator 陈述；但论文里更强的定量下界（如矩阵乘法每个 n 的 n^(9/4)/2 门下界、网格族 n^Ω((log n)^(1/12)) 下界、sunflower 的具体常数）“仍未形式化”。（[Lean 文档 379](https://github.com/openai/math/blob/main/lean/docs/379.md)；[Lean 文档 380](https://github.com/openai/math/blob/main/lean/docs/380.md)）
- VP ≠ VNP 的“先后”之争：OpenAI 的《VP and VNP are different》以“November 23 edition”名义发布，提交时间为 2026-11-24 01:20 UTC（曼谷时间 11 月 24 日 08:20），晚于上期报道的 Anthropic formal-math 提交（曼谷时间 11 月 24 日 03:04）；history.md 写明该结果“于 2026 年 11 月 6 日获得”，README 又称“在署名、优先权和同期工作上完全听从数学界”。HN 上有人建议实验室取得结果时先公布哈希。（[OpenAI VP≠VNP README](https://github.com/openai/math/tree/main/preprints/VP-and-VNP-are-different-November-23-2026)；[HN, 2026-11-25](https://news.ycombinator.com/item?id=50632756)）
- DeepMind（11 月 23 日）：用 Gemini 4 Agent 团队针对 Lean 写成的形式化问题规格合成量子程序并证明正确性和资源成本，团队通过 wiki 共享知识、每四小时开一次“会议”。结果：一种 Grover 实现提速 2.57 倍，把数值载入量子态的 arcsin 例程提速 290 倍，惯性约束聚变相关计算成本降 11.8 倍（纠错量子比特从 5,650 降到 4,338），细胞色素 P450 模拟提升 2.5 倍（481 降到 333 量子比特）。Lean 库、规格和已验证解开源。（[Google DeepMind, 2026-11-23](https://deepmind.google/blog/finding-faster-quantum-algorithms-with-agents-and-formal-verification/)；[arXiv 2611.09822](https://arxiv.org/abs/2611.09822v3)；[GitHub](https://github.com/google-deepmind/formal-quantum-computation)）
- OpenAI（11 月 24 日）：预印本称 GPT-6 系列可只靠推理和通用代码设计蛋白质结构与序列，不调用专门的生物模型；内部研究模型在 14 项蛋白质任务的多数上持平或超过专门模型，但完整结构预测仍明显落后。与 Onava 合作的湿实验中，基于 GPT-6.2 预发布版骨架设计的 minibinder 在 5 个靶点上都至少有一个出现结合迹象；但序列由 SolubleMPNN 生成，候选筛选用了 Boltz-2、ESMFold2 等专门模型，OpenAI 明确说尚不能证明“零样本端到端”设计。（[OpenAI, 2026-11-24](https://openai.com/index/gpt-6-models-demonstrate-intrinsic-protein-design-capabilities)）

**为什么重要**
- 两天内 Anthropic、OpenAI、DeepMind 都在发布“Agent 发现 + Lean 验证”的成果，形式化验证正成为 AI 科研产出的信任锚点。但 OpenAI 自己也承认未形式化的结果“可能有问题”，ω = 9/4 这类颠覆性结论在专家核查前只能当作声称。
- 对 Agent 开发者来说，可复用的模式是一样的：可机器检查的规格（Lean 规格、湿实验），加上多 Agent 并行探索和共享笔记。DeepMind 的“wiki + 定期会议”就是一种多 Agent 协作 harness。

**接下来关注**
- 复杂度理论和组合学专家对矩阵乘法、LP、sunflower 结果的核查；OpenAI 生物安全评估（Preparedness Framework）如何约束蛋白质设计能力的开放。

### 2. MCP 两周年：Skills over MCP、Tasks、Elicitation

**发生了什么**
- Anthropic 宣布 Skills over MCP 进入 public beta：MCP 服务器可随工具发布 skills（最佳实践、分步工作流、按账户或组织定制的 playbook），Claude 只在需要时加载，skills 随服务器更新，用户无需另装。Shopify 用它端到端设计和更新店铺，HubSpot、Atlassian 已接入，Carta 即将上线。Pro、Max、Ultra 默认开启，Team 需管理员启用，Enterprise 即将支持。（[Claude, 2026-11-24](https://claude.com/resources/articles/skills-over-mcp-tasks-and-more)）
- Tasks 与 Elicitation GA：Tasks 让服务器在后台跑耗时操作甚至完整 Agent 循环，Claude 继续工作、结果就绪后再取（ZoomInfo 用于账户研究）；Elicitation 让服务器中途通过表单或链接向用户确认，Supabase 在创建付费项目和执行破坏性 SQL 前确认费用，Railway 在删除服务前确认，GitHub 要求用户输入仓库名才允许 Agent 删除。File Uploads 扩展即将上线，文件不经过上下文窗口直接传给服务器。这些都属于开放 MCP 规范及扩展，兼容客户端都能用。（[Claude, 2026-11-24](https://claude.com/resources/articles/skills-over-mcp-tasks-and-more)）
- 背景：据 The New Stack 采访，Skills over MCP 9 月成为官方 MCP 扩展，Tasks 10 月先在 Claude Code 中 beta；维护者 Soria Parra 称很多人用 MCP 服务器“暴露的是完整的 Agent，而不只是单个动作”。（[The New Stack, 2026-11-24](https://thenewstack.io/mcp-skills-tasks-claude/)，二手）
- 客户端同步：Claude Code v2.1.332 加入来自 MCP 服务器的 skills（beta，在 `/` 菜单显示为 `server:skill`），新增 `PreSkillShellCommand` hook，可在 skill 或命令加载时拒绝其中的内联 shell 命令；还修复了本地 MCP 服务器刷屏 stdout 时终端冻结、无视 Ctrl+C 的问题。（[GitHub, 2026-11-25](https://github.com/anthropics/claude-code/releases/tag/v2.1.332)）

**为什么重要**
- MCP 从“工具目录”变成“带说明书、能后台干活、会请示的远程 Agent”，Claude 与服务器的关系更像 Agent 对 Agent。这与上期 AWS 把 MCP、A2A 端点纳入 WAF，以及同期 SkillPrivus 发现 54.5% 的 skills 有潜在隐私违规是一条线：skills 由服务器动态下发后，供应链和提示注入面也一起变大，`PreSkillShellCommand` 这类拦截点就是对应的防线。
- Elicitation 把“花钱、删数据前问人”标准化到协议层，正好对应下文 ShellBench 发现的安全失误。

**接下来关注**
- OpenAI、Google 等客户端对 Skills over MCP 和 Tasks 的支持进度；服务器下发 skills 的签名、权限声明和审计机制。

### 3. ShellBench：真实日常任务上，最强 Agent 也只过六成

**发生了什么**
- OpenClaw Foundation 联合 Parsewave、Hugging Face、Red Hat、UC Berkeley 发布 ShellBench：基于 1000 多万条匿名真实 Agent 交互提炼 100 个任务（90 个按 721 条标准评分，其中 381 条是安全标准；10 个用代码测试），每个任务配一个真实感工作区（中位数 188 个文件，含邮件、日历、表格、收据、PDF 和钓鱼信息），所有标准全过才算完成。共评测 12 个模型、5 个 harness（Claude Code、Codex、Hermes、OpenClaw、Pi），53,100 次评分运行。20 个任务公开、80 个留出，完整论文待发布。（[OpenClaw Blog, 2026-11-24](https://openclaw.ai/blog/shellbench/)；[Kaggle 榜单](https://www.kaggle.com/benchmarks/openclaw-foundation/shellbench)）
- 结果：GPT-6 Astra 62.5%、Claude Fable 5.2 61.9%、GPT-6.1 Sol 61.4%，前三相差 1.1 个百分点，但每次运行估算成本分别为 1.10、0.83、0.19 美元；DeepSeek V4.1 Flash 39.7%，约 5 美分。GPT-6 Astra 三次中至少一次成功 75.1%，三次全成功只有 48.8%。15.7% 的运行至少违反一条安全要求，正确性全过的 26,151 次运行里仍有 9.9% 违反安全要求。一个聚餐规划任务中 531 次有 522 次选对餐厅，但 331 次仅因没注明依据的文件而失败。（[OpenClaw Blog, 2026-11-24](https://openclaw.ai/blog/shellbench/)）
- 模型与 harness：同一 harness 内最好与最差模型的中位差 45.7 个百分点，固定模型换 harness 的中位差 6.2 个百分点；各 harness 平均通过率 OpenClaw 45.23%、Pi 45.22%、Hermes 45.11%、Codex CLI 45.04%、Claude Code 42.87%（OpenClaw 是发布方，结论需留意利益相关）。Pi 每次运行中位 1.31 分钟，OpenClaw 2.86 分钟。（[OpenClaw Blog, 2026-11-24](https://openclaw.ai/blog/shellbench/)）
- 据 TechCrunch（二手，经 ToolSift 转引）：Agent 在接孩子放学的安排上 79.5% 出错，40.3% 推荐了重复或错误的发票付款，18.6% 没能保护敏感的银行上传 token；测试未在 Muse、Dots、Claude Duet 等消费级应用内进行。（[ToolSift, 2026-11-25](https://toolsift.ai/agent-news/2026-11-25/)；[TechCrunch, 2026-11-24](https://techcrunch.com/2026/11/24/even-the-best-ai-agents-struggle-with-everyday-life/)）

**为什么重要**
- 它把“个人 Agent 能否无人看管地做家务行政”量化了：可靠性（pass^3）和证据保留比单次通过率更说明问题。对 Agent 开发者，提升方向不只是减少幻觉，还有需求追踪、完整性自检、引用证据。
- “模型比 harness 重要，但 harness 决定耗时和成本”，对选型和自研 harness 都是实用参考。

**接下来关注**
- 论文正式发布后的任务细节和 LLM judge 误差（博客承认部分波动可能来自判分器）；Meta、Anthropic 等消费级 Agent 是否公布在 ShellBench 上的表现。

### 4. RSI 观察：METR 解读 OpenAI 预训练 loss 的 7 倍加速

**发生了什么**
- METR（Ajeya Cotra 等）11 月 24 日发文：OpenAI 公开的 13 个模型的 base model log-perplexity（固定的内部代码库留出集）显示，2026 年初以来下降速度约为 2022 到 2025 年的 7 倍；若保持，GPT-3.5 到 GPT-4.1 用三年走完的降幅约 6.5 个月就能走完。按标准 scaling law，loss 进展本应越来越慢。（[METR, 2026-11-24](https://metr.org/blog/2026-11-24-interpreting-a-recent-acceleration-in-pretraining-loss/)）
- METR 内部没有共识，列出三种解读：数据可能因过拟合或代码数据泄漏而高估进展；基准分数才是真实能力的度量（Epoch ECI 并未同步加速）；或 perplexity 是更深层的能力指标，预示未来六个月能力普遍加速。脚注引用 OpenAI 原文“加速主要来自长期研究和算力投入，自动化只占较小部分，但最新模型已有 AI 做出的有意义的设计贡献”，并引用 METR 自己此前对 Anthropic 的评估“2026 年 10 月的加速约 80% 归因于 AI”。脚注还指出 looped transformer 这类每 token 算力更多的架构，可能降低 perplexity 多于提升下游能力。（[METR, 2026-11-24](https://metr.org/blog/2026-11-24-interpreting-a-recent-acceleration-in-pretraining-loss/)）
- METR 希望各实验室补充：其他留出集（最好是 2022 年前、含书籍和科学写作）上的 log-perplexity、每个模型预训练结束的大致日期、预训练算力、人力和实验算力随时间的变化。（[METR, 2026-11-24](https://metr.org/blog/2026-11-24-interpreting-a-recent-acceleration-in-pretraining-loss/)）

**为什么重要**
- 这是第三方评测机构第一次系统讨论 11 月 23 日日报报道的 Pachocki 曲线。如果加速确实有相当部分来自 AI 参与研发，就是 RSI 闭环在预训练环节的直接证据；METR 点明了需要哪些数据才能区分“一次性跃升”和“复利式加速”。
- 结合主题 1 的数学成果和上期 GLM-5.4 的 looped 架构，能力信号（数学、科研）在加速，而通用基准没有同步，两者之间的解释缺口正是监管和“发展上限”提议的关键。

**接下来关注**
- OpenAI 是否公开其他留出集和训练日期；Anthropic、Google 是否像 Microsoft 一样用同一数据集报告分数。
