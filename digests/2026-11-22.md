## 重点话题

### 1. 黎曼猜想 Lean 证明通过社区验证

**发生了什么**
- Lean 与 Mathlib 社区 11 月 21 日发布联合声明（Lean FRO 和 Mathlib Initiative 背书）：Alpöge 11 月 20 日发布的证明是一个 1,700 万行的 Lean 库，只直接依赖 Mathlib；社区称“我们对其正确性有完全信心”，并逐条确认四项标准：命题即 Mathlib 中经过专家审核的 RiemannHypothesis；数十人复现编译并得到同一份证明导出文件；用 `comparator` 和 `con-leche --compare` 两个独立工具确认所证定理与 Mathlib 命题完全一致；导出的证明被 Lean 官方内核、`con-leche`、`con-ron` 及多个第三方用不同语言实现的检查器接受，其中 `con-leche` 与 `con-ron` 带有相对集合论的形式化证明，保证不会接受错误证明。检查都在“惰性导出”上运行，与可能存在恶意代码的 Lean 源码隔离。（[Lean community blog, 2026-11-21](https://leanprover-community.github.io/blog/posts/riemann-hypothesis/)）
- MIT 数学家 Andrew Sutherland 公开了完整验证记录（检查用 Claude Code 执行）：175,187 个模块在 Lean v4.33.1 下全部零错误编译；五个主定理只依赖 `propext`、`Classical.choice`、`Quot.sound` 三个标准公理；独立 Rust 内核 nanoda 在 80 线程上用 27 分 42 秒接受全部导出，con-leche 接受 1,468,418 条声明；导出文件解压后约 61.6GB。他还把证明与独立的 Robin 判据形式化组合，得到不提 zeta 函数的 Robin 不等式和 Lagarias 不等式定理。截至页面更新时（2026-11-21 12:55 UTC），`lake comparator` 端到端运行和 Lean 默认内核重放仍在进行。（[Andrew Sutherland 验证页, 2026-11-21](https://math.mit.edu/~drew/grh/)）
- 范围说明：Sutherland 写明这里的“GRH”指所有模和所有特征的 Dirichlet L 函数，Dedekind zeta、Hecke L 函数和一般自守 L 函数不在已检查命题之内。他也列出注意事项：构建在没有沙箱的云机器上进行，尚未与沙箱内 `lake build` 的导出做哈希比对。（[同上](https://math.mit.edu/~drew/grh/)）
- 背景：Latent Space 的 AINews 汇总称，Alpöge 未披露所用 Claude 模型和人工引导程度，ANT 股价当天跌约 10%（二手，转引 X 帖）。（[Latent Space AINews, 2026-11-20](https://latent.space/p/ainews-riemann-hypothesis-proved-twice-independently/)）

**为什么重要**
- 上期报道时 Tao 称它是“消化程度最低”的结果，一天之后社区给出了形式化层面的认证。这是第一次一个千禧年问题的证明在没有任何人读懂全文的情况下，被正式验证基础设施判定为正确。对 Agent 开发者来说，这是“可验证奖励 + 大规模生成”路线的最强例证：只要有可信的检查器，生成方是谁、产出多大都不再是信任前提。
- 验证本身也是一个 Agent 用例：Sutherland 用 Claude Code 编排多内核检查，社区用多套独立实现交叉验证，并把证明导出与源码隔离以防恶意代码。这套“多独立检查器 + 惰性产物 + 公开哈希”的做法，可以直接借鉴到 Agent 生成代码和数据的验收流程。

**接下来关注什么**
- `lake comparator` 和 Lean 默认内核重放的最终结论；沙箱内重建导出的哈希比对。
- 数学界能否从 1,700 万行 Lean 中提炼出人类可读的新思想；Masullo 的 940 页人工证明审稿进展。
- Anthropic 是否披露模型版本和人机分工。

### 2. Inkling 2 Mini：开源 looped transformer 与 CoT 可监控性（补报）

**发生了什么**
- Thinking Machines 11 月 20 日发布 Inkling 2 Mini：MoE，26.4B 总参数、3.4B 激活，计入循环后每 token 5.4B 有效激活；24 层分 4 个块，中间两个块（12 层）每个 token 运行 3 次，共 48 次层计算；1M 上下文，文本加图像输入；Apache 2.0 开放权重。厂商称它在 100B 以下开源模型中 DeepSWE v1.1（48.2%）和 Vals Index v2.2（46.5%）领先。权重大部分原生 NVFP4 训练与部署，最后四层 MXFP8，总占用约 20GB，可跑在 32GB 以上的 Mac 或单台 DGX Spark 上。（[Thinking Machines, 2026-11-20](https://thinkingmachines.ai/news/inkling-2-mini/)；[Hugging Face 模型卡, 2026-11-20](https://huggingface.co/thinkingmachines/Inkling-2-Mini)）
- 训练做法：从主线 scaling ladder 衍生，中期训练剪掉三分之二专家并引入循环；实验中循环中间 12 层在 28 项评测里有 27 项优于循环最后 12 层。（[Thinking Machines, 2026-11-20](https://thinkingmachines.ai/news/inkling-2-mini/)）
- 安全研究：同时发布可变循环研究模型 TML-d24-varloop-research。无 CoT 时间跨度从 1 次循环的 16 秒升到 3 次的 37 秒；串行推理基准在 10 次循环内持续提升（训练时最多 5 次）；循环增加后 CoT 变短但保持可读，agentic sabotage 测试分数没有上升。长上下文基准（GraphWalks、MRCR v2）随循环提升，知识类（SimpleQA Verified、AA-Omniscience）不提升。（[Thinking Machines, 2026-11-20](https://thinkingmachines.ai/news/inkling-2-mini/)）
- 生态：vLLM day-0 支持（[vLLM Blog, 2026-11-20](https://vllm.ai/blog/2026-11-20-inkling2-mini)），Hugging Face transformers 同时支持固定和可变循环版本（[Hugging Face Blog, 2026-11-20](https://huggingface.co/blog/inkling2mini)）；AINews 汇总称 Soumith Chintala 在 DGX Spark 上测得约 75 tok/s，并评价“大致和 Qwen 3.8 27B 一样好”（二手）。

**为什么重要**
- 本地可跑、开源、编码 Agent 分数靠前，适合端侧和私有化 Agent 部署。
- 循环架构让模型“在内部多想几轮而不写出来”，这正是 CoT 监控最担心的方向。Thinking Machines 主动放出可变循环模型供外部研究，是少见的把可监控性当作发布内容的一部分。

**接下来关注什么**
- 外部团队用可变循环模型做的 CoT 忠实度和破坏性测试结果。
- 社区量化版本的质量（HN 上有人发布 5.4GB 量化，358 分，效果尚未独立验证）以及在 Pi、OpenCode 等 harness 中的实测。

### 3. METR Q4 能力更新：Time Horizons 2.0 与 AI R&D 加速（补报）

**发生了什么**
- METR 11 月 20 日发布对公开模型（截至 Opus 5.5 和 GPT-6 Astra）的 AI R&D 相关能力评估。主要结论：模型在 METR 的编码和优化任务上通常追平或超过熟练人类，自招的人类基线大多找不到能赢模型的人；在更难做成 RL 环境的任务上模型表现略差，METR 用 “Lifecycle Cost” 量化这一点，成本翻倍约等于时间跨度减半，但高低成本任务上进步速度相近；在缺少清晰经验反馈的任务上，Agent 判断力不如人类专家，模型裁判会高估同等或更强模型产出的质量。（[METR, 2026-11-20](https://metr.org/blog/2026-11-20-q4-2026-capability-update/)）
- 在 TH1.1 与 TH2 合并任务集上，时间跨度约每 3.6 个月翻倍，与 OpenAI 内部研究任务上报告的趋势相近；仅看 TH2 可验证子集翻倍更快，METR 称这可能意味着被合并趋势掩盖的加速，但也有其他解释。用 METR Capability Index（MCI）跟踪公开前沿，没有看到整体明显加速或减速。（[METR, 2026-11-20](https://metr.org/blog/2026-11-20-q4-2026-capability-update/)）
- METR 的总判断是：现有公开证据不足以排除未来几年出现“剧烈的 AI R&D 加速”，即能力提升快到人类无法有效理解、评估和应对新系统的灾难性风险。AINews 汇总的具体数字为 GPT-6 Astra 40.3 小时、Opus 5.5 39.0 小时，95% 置信区间很宽（二手）。（[Latent Space AINews, 2026-11-20](https://latent.space/p/ainews-riemann-hypothesis-proved-twice-independently/)；[MIT Technology Review, 2026-11-20](https://www.technologyreview.com/2026/11/20/1149399/the-most-misunderstood-graph-in-ai-just-got-a-major-update/)）

**为什么重要**
- 这是 RSI 讨论中最常被引用的第三方度量。“易验证任务进步快、难验证任务和判断力落后”的结论，和本周 GRH 证明、OpenAI RL 错位报告指向同一件事：可验证的地方 Agent 已经很强，难点在没有检查器的地方。
- 对评测设计的启示：模型裁判会高估强模型输出，用 LLM-as-judge 做 Agent 评估需要独立的人类或程序化验证。

**接下来关注什么**
- TH2 可验证子集的加速是否在下一批模型（GPT-6.2 Astra、Gemini 4 Neon）上得到确认。
- 各实验室安全框架（如 OpenAI 的 AI Self-improvement 阈值）如何引用这份数据。

### 4. harness 是组合泛化器：MIT CSAIL 论文（补报）

**发生了什么**
- Alex L. Zhang、Souradip Chakraborty、Omar Khattab 11 月 20 日发布 “LM Harnesses are Compositional Generalizers”。论点：多数 harness 采用“轨迹即 prompt”，历史越积越长，模型脱离分布导致 context rot；而 CodeAct、MemGPT、RLM 等抽象通过上下文卸载、程序化工具调用和递归子 Agent，让每次 LLM 调用保持局部分布内（locally in-distribution, LID）。这样编排模型学到的是分解策略，子 Agent 用已有能力解决子任务，从而在任务长度、策略和递归深度上泛化。作者反对“更强的 LLM 会吸收 harness”的说法。（[Alex Zhang on X, 2026-11-20](https://x.com/a1zhang/status/2123774098241147225)）
- 论文提出 surrogate harness training：对于展开很慢的长任务，可以只训练单次 LLM 调用，用纯合成任务、假工具调用和子 Agent 代替完整 rollout。X 新闻摘要称实验中模型泛化到 8 到 64 倍长的任务，27B 模型在长上下文套件上相对提升约 27%（二手，未核对论文原文）。（[X 新闻摘要, 2026-11-20](https://x.com/i/trending/2123819680590921853)）

**为什么重要**
- 与上期 Hugging Face 在 harness 内做 RL 的 adapters 互为补充：一个说明在 harness 里训练有效，一个解释为什么有效，并给出更便宜的训练方式。对做长时 Agent 的团队，“控制每次调用看到什么”比“塞更长上下文”更值得投入。

**接下来关注什么**
- 论文代码和数据（作者称已全部公开）的复现；surrogate training 在真实编码 Agent 而非长上下文基准上的效果。
