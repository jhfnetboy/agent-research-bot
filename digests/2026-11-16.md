## 重点话题

### 1. Agent 框架被武器化：FBI 就 ARTEX 发布 FLASH 警报

**发生了什么**
- FBI 于 2026-11-13 发布 FLASH-20261113-001。警报称 ARTEX 是用 Go 写的开源、LLM 驱动的多 Agent 渗透测试平台，自身不带模型，可接入 Anthropic Claude、OpenAI GPT 以及 DeepSeek、GLM、Grok、Kimi 等模型，把自然语言写的战术目标翻译成由专门 Agent 执行的命令。自 2026 年 8 月起，多类攻击者用它攻击金融、政府、科技、国防、半导体、能源、医疗等行业，部分入侵从初始目标到特权访问不到 3 小时；点名的案例包括针对韩国金融机构、泄露约 67,000 人个人信息的攻击，以及影响 ConnectWise Cloud Backup 客户、可进入 2,250 多个下游租户的供应链入侵。FBI 认为它特别擅长打“边缘系统”：合作伙伴和供应商门户、移动后端、员工应用、遗留服务、第三方集成。警报为 TLP:CLEAR，附 IOC 和缓解措施。（[FBI IC3 FLASH, 2026-11-13](https://www.ic3.gov/CSA/2026/261113.pdf)）
- The Record 报道，ARTEX 于 8 月由 GitHub 账号 “Autumn-27” 发布，开发者被识别为中国安全工程师 Li Puhua；他在 10 月 8 日发声明称工具被滥用、否认责任，随后删除了仓库。（[The Record, 2026-11-14](https://therecord.media/artex-ai-tool-fbi-flash-alert)）BleepingComputer 同样把 ConnectWise 供应链事件与 ARTEX 关联。（[BleepingComputer](https://www.bleepingcomputer.com/news/security/fbi-warns-artex-ai-hacking-tool-is-powering-global-cyberattacks/)）据 ToolSift 汇总，FBI 还提到攻击者自建实例上最常见的是中国模型，DeepSeek Flash 系列因便宜且在“渗透测试”包装下护栏不明显而占主导，Censys 发现 1,600 多个公网暴露的 ARTEX 控制台（二手，未在 FLASH 原文中逐条核对）。（[ToolSift, 2026-11-16](https://toolsift.ai/agent-news/2026-11-16/)）
- FBI 给出的立即措施包括：盘点全部对外应用（含边缘系统），把管理、备份等敏感服务限制在可信网络，尽量上零信任访问；多租户应用权限最小化，按 application ID 而非显示名排查受影响的 ConnectWise 应用；IOC 中的短期 IP 要先对照当前遥测再封禁。（[TSN, 2026-11-14](https://tsnmedia.org/fbi-flash-artex/)）

**为什么重要**
- 这是执法机构第一次就一个具体的“Agent harness”发正式警报。真正的危险不在某个模型，而在 harness：把侦察、利用、提权、外传串起来的编排层，可以换任何模型来跑。模型侧的拒答护栏，挡不住一个可以随时换成便宜开放模型的框架。
- 和 13 日日报里 Railway 被盗刷事件（Wiz 判断用了类似 ARTEX 的 harness）、15 日 Epoch 评测越界事件放在一起看：Agent 的“坚持尝试、并行探测”能力同时出现在攻击方、被测模型和防守方身上。对 Agent 开发者来说，自己产品里的 Agent 凭据、MCP 端点、Agent 控制台，本身就是这类工具最喜欢的“边缘系统”。

**接下来关注**
- 模型厂商是否针对 ARTEX 类流量发布检测或封禁措施（FLASH 把“对 LLM API 的外连”列为行为指标）；GitHub 等平台如何处理 fork 和镜像。
- CISA 或其他国家机构是否跟进，ConnectWise 事件的完整影响范围。

### 2. 让模型写代码来调工具：Claude Code Code Mode 与 Agent 编排的“代码化”

**发生了什么**
- Claude Code 2.1.323（2026-11-12）加入 Code Mode，实验性、默认关闭，用 `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1` 打开。开启后 Claude 不再一次请求一个 Bash、Read 或 Edit，而是写一段 JavaScript，在一段代码里并行跑命令、把上一步结果传给下一步、只把需要的部分返回给模型；MCP 工具同样可调用。官方建议用于跨多文件的重复修改、需要先过滤再阅读的搜索、可并行的独立命令。（[Claude Code 文档](https://code.claude.com/docs/en/code-mode)；[CHANGELOG v2.1.323](https://raw.githubusercontent.com/anthropics/claude-code/v2.1.323/CHANGELOG.md)）
- 安全边界写得很明确：代码发起的每个工具调用仍经过 deny/ask 规则和 PreToolUse hook；auto mode 下分类器审的是整段代码而不是每个调用，并且看不到运行时算出来的值（例如从搜索结果里取出的路径），所以文档提醒必须控制的调用要靠规则或 hook 兜底。限制也不少：需 Claude 订阅或 Console 账号，不能经 gateway、Bedrock、Google Agent Platform 或 Foundry；HIPAA 和零数据保留组织不可用；只支持终端交互会话，不支持 `-p`、Agent SDK、VS Code 面板和云端会话；模型限 Opus 5.5、Sonnet 5.5、Haiku 5.5 和 Fable 5.2。（同上）
- 同一周，AWS 在 2026-11-13 给 WorkSpaces for AI agents 加入 Linux 和 Windows 11（BYOL）桌面，并在免费的 Agent Toolkit for AWS 里加了一个 WorkSpaces skill，教 Kiro、Claude Code、Codex 等 Agent 如何连接会话、在阻塞和轮询模式间选择、批量执行桌面动作省 token；Agent 还能通过标准 MCP OAuth 流程用 AWS 身份登录，短期 token 自动续期，权限沿用按工具的 IAM 规则，连接记入 CloudTrail。（[AWS Blog, 2026-11-13](https://aws.amazon.com/blogs/desktop-and-application-streaming/amazon-workspaces-for-ai-agents-adds-linux-windows-11-and-oauth-support/)）

**为什么重要**
- 逐个工具调用的“一问一答”循环，在多步任务上既慢又费上下文。让模型写代码一次编排多个调用，可以把中间结果留在执行环境里而不是塞回上下文。加上 15 日日报里 Antigravity 的 Dynamic Workflows（Agent 写 Python 调度子 Agent），两家头部编码 Agent 在一周内走向同一种形态。
- 代价是审查粒度变粗：审批从“每个动作”变成“一段程序”，而程序的行为取决于运行时数据。这正好呼应今天的 ARTEX 和上周的 Epoch 事件，说明在 Agent 编排层做确定性的权限规则和 hook，比依赖一次性的分类器判断更可靠。
- AWS 的做法是另一条思路：用 skill 文件教 Agent 怎么正确使用一个服务，用 MCP OAuth 把认证标准化。skill 加 MCP 正在成为“让 Agent 用好一个产品”的默认交付方式。

**接下来关注**
- Code Mode 是否进入 Agent SDK 和非交互模式，以及 Anthropic 是否公布 token 或时延上的对比数据（目前文档没有给数字）。
- OpenAI Codex 是否跟进类似机制；Codex 本周连发 0.171.0 alpha.1 到 alpha.7，正式版说明值得看。（[Codex Releases](https://github.com/openai/codex/releases/tag/rust-v0.171.0-alpha.7)）

### 3. 给购物 Agent 装“自主权旋钮”：EU Digital Fairness Act 第 26 条

**发生了什么**
- 欧盟委员会于 2026-11-11 正式提出 Digital Fairness Act（DFA），将以条例形式直接适用于全部成员国，并废止不公平商业行为指令。其中第 26 条专门规范“替消费者签订和履行合同的自动化系统”：提供这类 Agent 的商家必须给出易用、易懂、有效的工具，让消费者设置和随时修改参数；首次使用时，消费者必须明确选择（a）每份合同都先确认，（b）只确认某类合同、由消费者设定标准（包括价格上限和该选择的有效期），或（c）完全不确认；选择结果要以持久介质发给消费者。（[DFA 第 26 条文本](https://eu-digitalfairnessact.com/article/26)；[欧盟委员会提案 PDF](https://commission.europa.eu/document/download/0575d59f-554f-4a9e-b54b-e6b717175809_en?filename=Proposal+for+a+Digital+Fairness+Act.pdf)）
- 同条还要求：选择确认时 Agent 要展示关键的合同前信息；Agent 一旦因推荐某份合同收了钱或存在利益冲突，必须披露，并且无论用户选了哪档都要求逐单确认。（[DFA 第 26 条文本](https://eu-digitalfairnessact.com/article/26)）Pinsent Masons 的解读指出条款直接针对电商里“基于动态推理、只需极少人工输入”的 AI Agent（[Pinsent Masons, 2026-11-11](https://www.pinsentmasons.com/out-law/news/ai-agents-dark-patterns-digital-fairness-act)）；William Fry 认为第 26 条既覆盖零售商自家的购物助手，也覆盖跨商家的独立 Agent，且说明部分写明使用 Agent 不意味着放弃消费者权利（[William Fry](https://www.williamfry.com/knowledge/digital-fairness-act-targets-ai-agents/)）。

**为什么重要**
- 过去一周 Agent 支付密集落地：ChatGPT Wallet、Sierra 的 Poppy 1.0 上线全部 Shopify 店铺（14 日日报），以及 Meta Muse 开始替付费用户打电话给商家（见其他动态）。DFA 把“Agent 能替我花多少钱、什么时候必须问我”从产品设计选项变成法定义务，任何面向欧盟消费者的购物 Agent 都要内置分档授权和利益冲突披露。
- 对 Agent 协议的含义：Poppy、UCP 这类协议里的权限和确认字段，未来可能需要直接映射到 DFA 的三档选择和“价格上限加有效期”参数。

**接下来关注**
- 提案还需欧洲议会和理事会通过，条款细节可能改；各家 Agent 支付产品（OpenAI、Meta、Stripe、Visa 和 Mastercard 的 Agent token）如何调整默认授权模式。
